# Datasets

## Required input data

| Dataset | Type | Requirement |
| --- | --- | --- |
| **Project perimeter** ("forest mask") | Vector (polygon) | Covers the entire forest area to be processed. Must be **free of geometry/topology errors** (no duplicate nodes, overlaps, gaps) — otherwise the algorithm aborts. Particularly error-prone with multipolygons made up of many small parts (e.g. when forest roads are cut out of the perimeter). |
| **Vegetation height model (VHM)** | Raster | Resolution ≤ 1.5 m, covers the entire perimeter. Source e.g. LiDAR or stereo aerial image correlation. Scaled by the preprocessing tool to the resolutions 10×10m (stand formation) and 1.5×1.5m (crown coverage determination) and aligned together with the mixture-degree raster. |
| **Mixture degree (MG)** | Raster (optional) | Values 0–100, describing the coniferous proportion in % per pixel. Aligned by the preprocessing tool together with the 10×10m VHM raster. Raw data often comes in a different scale/direction — see [Caution: scaling of the mixture degree](workflows.md#phase-1-preprocessing) in preprocessing. |

All input data must be correctly georeferenced (no projection errors) and have NoData correctly defined. It does not necessarily have to be in the same coordinate system, but it is recommended to project all data into the same system beforehand.

### Geometry error checking (perimeter)

Check in QGIS with the standard tools **Check Validity** and **Repair Geometries**, and fix many simple errors directly.

## Intermediate/input data generated by TBk

The [preprocessing tool](workflows.md#phase-1-preprocessing) turns the raw data into the actual inputs for *Generate BK*:

| File | Description |
| --- | --- |
| `VHM_detail.tif` | High-resolution VHM (intermediate step) |
| `VHM_10m.tif` | VHM aggregated to 10×10m — main input for stand delineation |
| `VHM_150cm.tif` | VHM at 150cm resolution — for the crown coverage calculation |
| `MG_10m.tif` | Mixture degree, aligned to the 10m VHM (only if an MG input is provided) |
| `MG_10m_binary.tif` | Binarized mixture degree (only if an MG input is provided) |

## Output data

| File | Description |
| --- | --- |
| `TBk_Bestandeskarte.gpkg` | Main result: the stand map with attributes for dominant height (hdom), maximum height (hmax), crown coverage, mixture ratio and basic structure |
| `TBk_Project.qgz` | QGIS project for visualization, incl. 4 predefined print layouts (A1/A3, portrait/landscape) |

Details on the content meaning of the attributes: see [content documentation ↗](https://HAFL-WWI.github.io/TBk-Docs/tbk/).

## Configuration via TOML files

All tools can alternatively accept a `.toml` configuration file (parameter `config_file`), whose values override all parameters set in the dialog. The most important common keys (see `default_input_config.toml` in the plugin repository):

```toml
vhm_10m = ""                              # VHM 10m, main input
vhm_150cm = ""                            # VHM 150cm, for crown coverage
coniferous_raster = ""                    # Mixture-degree raster for stand mean
coniferous_raster_for_classification = "" # Mixture-degree raster for classification
perimeter = ""                            # Perimeter for clipping
output_root = ""                          # Output folder
del_tmp = true                            # Delete temporary files/fields
```

For reproducibility, the [workflows](workflows.md) themselves generate a ready-to-use config file containing the parameters actually used in that run. For technical reasons, the mandatory parameters still have to be filled in the UI dialog (with arbitrary values) — they are then overridden by the values from the config file, if one is passed.

Useful for making runs reproducible or for automating processing outside the QGIS UI.
